# Historical release audit · November 3, 2026

[Documentation](README.md) · [Validation history](validation.md) · [Releases](https://github.com/draco1738/prettTV/releases)

**All 17 published releases were already marked stable on GitHub** (`prerelease: false`, `draft: false`). No promotion was needed. This audit left every release flag, tag, asset, title and description unchanged and preserved v0.4.0 as Latest at the time of inspection. The separately staged 0.4.1 candidate is outside this historical audit.

GitHub's stable flag describes the publication channel. It does not establish that every feature works, that a release is free of bugs, or that an old version is recommended for installation. The findings below confirm specific historical evidence and retain its limitations.

## What was independently checked

- Resolved all 17 remote tags to their commit IDs, including annotated-tag targets. Every exact release commit has a successful GitHub Actions build linked below.
- Downloaded every historical prettTV APK and checksum file from its GitHub release. All **17 APKs** matched the published SHA-256, GitHub asset digest, byte count and preserved local release artifact.
- Verified each downloaded APK's signature, package `dev.zane.pretttv`, version name and version code. Every APK used the established certificate SHA-256 `46fecddaaff65d9500c6cfddee90e07c6ca3fe7941c8a405829258b5e7ff9ded`.
- Verified all **seven updater manifests**, from 0.2.0 onward, against the corresponding downloaded APK's version, package, hash and certificate. Earlier releases did not publish a manifest.
- Matched all **75 entries** across the published checksum files to GitHub's asset digests. Every release's RBTV metadata retained the same pinned SHA-256, `5e7f0b4eb571d4c662678cad8cd18254ec8abd55ead230d2f8e7ab684ff8f279`. This audit did not execute RBTV or independently retest ZIP installation.
- Cross-checked the [validation history](validation.md) and retained final deployment/test records. Failed intermediate attempts remain failures; later successful checks do not relabel them.

CI builds use a debug certificate and do not run the TV's Android instrumentation. Exact-commit CI success and production APK verification are separate checks. This audit did not rebuild historical binaries, reinstall old versions, or claim reproducible builds or fresh device tests.

## Other pushes and unresolved evidence

The retained GitHub Actions history contains **29 main-branch build runs: 28 successful and one failed**. The failed [59fd168f build](https://github.com/draco1738/prettTV/actions/runs/39374298626) used an Android 27 theme attribute in the website shortcut's Android 26 resources. [287fc212](https://github.com/draco1738/prettTV/commit/287fc212cc301a1dc66bdbe9d1e337645de43ee6) moved the attribute to version-qualified resources and its [replacement build passed](https://github.com/draco1738/prettTV/actions/runs/39375732398). The failed commit has no published release; it is not retroactively marked stable.

The subsequent [README-only push b84f876](https://github.com/draco1738/prettTV/actions/runs/40662220220) passed CI but did not create a new release. The source history also contains the tested 0.3.1 Settings repair, but no published 0.3.1 release/tag existed during this audit. No release was invented for it. The retired provisional 0.1.0 is not a current release.

The owner's current report that **Blind Pick and Rabbit Hole do not work** is an open functional issue during this audit. Historical passing controls, successful builds and a valid signature do not resolve it. In particular, the original Rabbit Hole record explicitly lacked positive live relationship results. This report therefore does not certify either experience as working on the current installation or recommend reverting to an older release. Their repair requires separate reproduced behavior and final-build validation.

Current reports of slow Home return and failed remote shortcuts likewise require their own repair and physical checks. Preserving historical stable flags does not dismiss those reports. No TV setting, installed app, Home preference or playback session was changed by this audit.
