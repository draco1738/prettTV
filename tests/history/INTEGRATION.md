# This TV only integration contract

History worker owns PlaybackHistory.kt, ViewingHistoryMode.kt and ContentRepository.kt; the parent additionally authorized the small ContentModel.kt policy field. No UI/backup edits.

**Implemented model API:** `HomeContent(viewingHistoryMode=choice)` creates the correct empty/reset value. The appended field defaults to COMBINED. `feature` permits suggestion fallback only in COMBINED, including when all locally watched hero titles are hidden. Discovery stays populated. All copy() paths preserve the field by default. Compile all HomeContent clients together; old constructor bytecode cannot be mixed with this changed model.

UI setting API: `ViewingHistoryMode.read(context)` or `.read(homePreferences)`; `.parse(String?)`; enum `.label` and `.name`. Persist `.name` at `pretttv` / `historySource` through the existing SettingsBackupGuard writer. `COMBINED` is the default for absent/invalid/wrong-type values. Successful mode change must invalidate/discard old displayed content and refresh/start repository, not just rebuild the old combined snapshot. Restore uses existing stop/generation/re-read lifecycle. No helper permission is enabled automatically.

Backup API: logical store `home`, key `historySource`, STRING enum names exactly `COMBINED` or `THIS_TV_ONLY`. `known` playback JSON now carries optional `localSnapshot` per row, using the same Program JSON keys as the parent row (id/title/detail/art/pkg/app/uri/pos/dur/type/imdbId/releaseYear/posterArt), plus optional boolean `providerAbsent`. Keep these through exports; nested validation should cover the same types/size as providerProgressBaseline. localSnapshot is metadata only: played:/position:/duration: remain the authority. providerAbsent prevents retained local metadata from becoming a false continuous-provider progress baseline when a provider row reappears. No new preference key is introduced for these snapshots. Missing legacy local snapshots use app-level metadata and local stored progress, never a guessed provider episode or deep link. The focused real LocalSettingsTransfer round-trip passes with the shared worker's historySource whitelist.

Playback API: `merge(rows, settingsGeneration = SettingsBackupGuard.generation, mode = ViewingHistoryMode.COMBINED)`. Existing positional generation calls remain source compatible. Mode switching retains both kinds of evidence. Confirmed metadata survives provider disappearance subject to the bounded known-record limit. Repository excludes unavailable/hidden packages from retained output.

Audit P1 API split (no schema changes):
- `confirm(p, position=p.position, duration=p.duration, eventAt=now, settingsGeneration=current)` is unchanged and reserved for deliberate user correction. MainActivity's existing explicit action needs no change.
- `observe(p, position, duration=0, eventAt=now, settingsGeneration=current)` is new. It accepts supplied local progress, sanitizes the Program to title/app/package/artwork and a local title ID, and uses the same guarded persistence path. It never defaults progress to provider fields or preserves episode/destination metadata.
- `match(pkg, labels): Program?` keeps its signature and ambiguity rules, but returns a title-only Program, not a provider episode: empty intent URI, zero position/duration, app-only detail. It does not infer episode equivalence from labels.
- PlaybackTracker calls the internal `PlaybackObservation.record(...)` boundary, which passes session progress to `observe`. Missing/nonpositive duration stays zero; position is clamped only against a positive session duration. It retains the 15-second sustained-playback/position gates and rejects known durations below three minutes. Host tests exercise that exact production boundary, not Android MediaController callbacks.
- Existing persisted local snapshots cannot be retrospectively classified as automatic versus deliberate; no speculative migration is attempted.

Refresh/caches: ContentRepository snapshots the live mode at load(), applies it to raw cached/fresh provider rows before automatic service inference and recommendations, and tags every published HomeContent. current() and deliverStatus() reject results if the live mode changed. OfflineSnapshot stores raw provider/catalog inputs, not the setting; decoding cannot restore a cached COMBINED HomeContent. Parent should close/recreate the repository, clear stale content with the mode-aware empty value, render, then startContent after the guarded preference write succeeds. Reset chosen source/rotation UI state only on that explicit user change, never merely because COMBINED was the default. No new start() parameter is required.

Focused command: `python tests/history/run_checks.py --repository --label green-integrated` (offline, cached E: compiler/SDK/JUnit/JSON and unchanged prior-release classes; no Gradle/device/network).
